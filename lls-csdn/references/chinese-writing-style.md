# 中文科普文风

## 读者和声音

优先服务计算机专业学生和初级开发者，同时让零基础读者能抓住主线。使用活泼但克制的科技自媒体语气，可自然混合：

- 直接面向读者的“你”；
- 陪伴式的“我们先来看”“接下来一起拆解”；
- 需要严谨时的中性技术说明。

没有真实运行记录时，禁止虚构“我测试了、我踩坑、我发现性能提升”等个人经历。可以表达有依据的作者判断，但必须与事实分开。

## 通俗化方法

- 术语首次出现采用“中文名称（English Term）”。没有公认中文译法时保留英文，不强行造词。
- 先说明它解决的具体问题，再引入定义。
- 可以使用生活化类比，但类比后必须说明边界，不能让类比替代真实机制。
- 代码只有明显帮助理解时才出现，优先引用官方最小示例，并在附近注明“根据官方文档整理，本文未运行验证”。
- 段落保持短而完整。每段聚焦一个意思，避免一行一句的机械节奏。

## Emoji

全文使用约 **4 至 8 个 Emoji**，用于“30 秒看懂”、关键转折、风险和总结等少量位置。不要连续堆叠，也不要把 Emoji 放入代码、链接、引用或技术标识符。

## 去 AI 味

删除以下模式：

- “随着科技飞速发展”“在当今数字化时代”等空泛开场；
- “值得注意的是”“毋庸置疑”“总而言之”等无信息过渡；
- 每节都使用相同的三段式和强行排比；
- 只有形容词，没有机制、来源或数字的评价；
- 把普通功能描述成宏大行业转折。

禁用无证据的“颠覆、封神、神器、必须学、震惊、史上最强”。如果热度有充分证据，也优先陈述具体增长或讨论背景，而不是使用夸张标签。

## 标题尺度

推荐形式：

- `技术名是什么？它如何解决某个具体问题`
- `这个 GitHub 项目，想把某件复杂事情变简单`
- `从问题到架构：一篇文章看懂技术名`

标题必须让读者知道文章在讲什么；吸引力来自具体问题、用途或反差，不来自隐瞒主题。
