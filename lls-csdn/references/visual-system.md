# 视觉系统

## 标准视觉组合

每篇标准文章尽量包含：

1. 漫画科普风封面；
2. 官方界面、官网或 GitHub 仓库截图；
3. 核心架构图；
4. 正文中的功能或同类工具对比表；
5. 只有存在可信真实数据时才制作性能图表。

不要为了数量重复展示同一信息。项目没有可视化界面时，用官方仓库关键页面或文档截图代替界面图。

## 来源顺序

`官方已有素材 > 官方页面自行截图 > 图像生成工具 > HTML/CSS 后备模板`

禁用来源不明的网络图片。官方素材保留官方远程 URL 和来源链接；原创图片上传 CSDN。官方外链不能稳定显示时，也可以上传 CSDN，但不得删除来源说明。

## 封面规范

- 固定尺寸 `1280 x 720`，16:9。
- 固定漫画科普版式，主标题不超过两行。
- 配色：青色 `#12B8C4`、橙色 `#FF8A3D`、深灰 `#263238`、白色。
- 技术 Logo 保持原样，不变形、不改色、不伪造官方联合品牌。
- 不添加固定栏目角标、账号名称或水印。
- 场景必须体现该技术的真实用途，避免只有抽象光效或通用“AI 大脑”。

优先使用图像生成工具制作主题画面；工具不可用时，复制并填写 [comic-cover-template.html](../assets/comic-cover-template.html)，再用浏览器或 Edge 截图输出 PNG。

## 架构图

只有系统包含三个以上有意义的组件时才制作架构图：

- 使用真实组件和数据流名称，节点优先中文，技术专名保留英文；
- 根据官方架构制作时注明来源；
- 根据公开资料归纳但非官方提供时，在图内显著写明“概念示意图”；
- 不确定的连接不能画成确定事实；
- 同时保留 Mermaid 源码和渲染 PNG。

## 工作目录

将生成和截图过程文件放在：

```text
E:\雷大帅的博客文章\.lls-csdn-work\<slug>\
```

最终 Markdown 只引用已上传 URL；上传不可用时保留相对路径和图片待上传注释。每张图都写有信息量的中文替代文本。
